The problem

To your IDE, Odoo doesn't look like normal Python

Odoo's ORM works in ways a normal Python type-checker can't see.

invisible to your IDE

_inherit merges everywhere

One model can be built from many _inherit extensions spread across different addons. A normal Python plugin only sees one class at a time.

no static type

env['model'] is just a string

self.env['res.partner'] has no real type. Every .search(), .browse(), or .filtered() call after it is untyped too.

opaque text

XML, QWeb and SQL are just text

Field names in <field name=>, domain tuples, and cr.execute(...) strings are just plain text. No checking, no jumping to the real code.

Odoo DevKit works by reading your Odoo source directly, instead of guessing from a list of snippets.

Features

Everywhere Odoo touches your code

One engine handles completion, navigation, and checks across every file type in your Odoo addon.

models.py

Models, fields, and types

  • Model & field completion: Go to Declaration for _name, _inherit, env[...], and relational fields
  • Recordset typing: precise inference for self, ORM calls like sudo(), and Form
  • Dependency guard: a warning the moment a model falls outside your addon's depends list
templates.xml

QWeb and Owl templates

  • Context-aware directives: t-* completion, plus typed Python inside eval=/domain=/context=
  • Live XPath resolution: jump from <xpath expr=> straight to the matched node
  • CSS completion: class=/id= inside templates Pro
component.js

JavaScript and Owl components

  • Bi-directional navigation: jump between JS components and XML templates
  • Modern & legacy modules: @addon/path and odoo.define resolve to the same file
  • Typed state & props: completion for registry.category(), useService(), state, and props
queries.sql

SQL support PyCharm Pro

  • Injected SQL: PostgreSQL highlighting inside cr.execute(...) and constraints
  • Model-aware completion: table and column suggestions synced to Odoo models
  • Go to Declaration: jump from a SQL string straight to the Python field
problems.log

Inspections and refactoring

  • Version-aware warnings: deprecated syntax (<tree>→<list>, attrs=) matched to your Odoo version
  • Dependency checks: unresolved models, fields, and Selection values flagged
  • Odoo-smart refactoring: Find Usages and Rename across models, not just class names
Under the hood

Built for large, multi-addon Odoo codebases

The hard parts of Odoo's ORM are exactly what break simple tools, or make them slow. Odoo DevKit is built around them.

▸

Multiple Odoo versions, kept separate

Works with several Odoo versions in one project without mixing them up. Lookups are scoped to each addon's Odoo version and dependencies.

▸

_inherit vs _inherits, handled correctly

SQL columns and ORM fields follow different rules for _inherit and _inherits. Odoo DevKit models both correctly instead of treating them as one mechanism.

▸

Stays fast on heavily-extended models

Uses a search index instead of re-reading every file on each keystroke, even on a model extended across many addons.

▸

Tested against Odoo source

Automated tests check behavior against Odoo's own source code across supported versions.

FAQ

Good to know

Which IDE do I need?

Today, PyCharm Community or Professional, 2026.2 (build 262) or newer. SQL and CSS features need PyCharm Professional specifically, with the matching bundled plugin enabled. JavaScript and Owl support works in both editions, limited by PyCharm Community's own, more restricted JavaScript support.

Will Odoo DevKit support other IDEs?

PyCharm is the only IDE we support today. The core engine isn't tied to one editor, so other IDEs may come later. Let us know which one you want.

Which Odoo versions are supported?

Odoo DevKit supports Odoo 10+ and detects the active version from your project source and manifests. Different Odoo versions can sit in the same workspace without clashing.

Does my code ever leave my machine?

Code analysis and indexing run locally inside your IDE. Odoo DevKit does not upload your source code.

Is there a free trial?

Yes. JetBrains Marketplace offers a 30-day trial before you need to activate a license.
