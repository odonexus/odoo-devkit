Everywhere Odoo touches your code

None of this is a snippet library. Each feature reads the addon you have open and its real _inherit chain.

models.py

Imports that resolve to real files

odoo.addons is a namespace Odoo builds at runtime, not a real package, so plain Python support can't follow an import into another addon. Odoo DevKit locates the addon on disk and resolves the import, whether it sits in your project, a dependency, or a sibling workspace module.

models.py

A dozen _inherit classes. One model.

Odoo builds one model out of _inherit classes scattered over a dozen addons, and _inherits delegation follows different rules again. DevKit rebuilds that merge, so self.env[...] carries a real, chainable type through ORM calls, and a field from outside your depends is flagged before you run anything.

⤢ Click to enlarge
views.xml

Views your IDE can read

To most tools a <field name=> attribute or a domain tuple is plain text, so a typo surfaces only when the view fails to load. DevKit resolves the model behind it, following inherit_id and <xpath>, and a gutter icon jumps to the matched node in the parent view.

⤢ Click to enlarge
xml / csv

One external ID system, many data files

<record>, <template> and a CSV row all declare the same kind of external id. DevKit indexes the three identically, so Go to Symbol, Ctrl+click and Find Usages land on the declaration wherever it lives.

⤢ Click to enlarge
templates.xml

Templates that know what's in scope

DevKit models the QWeb engine itself: every t-* directive, plus the exact variables Odoo puts in scope for each one, from env and the record's fields down to an earlier t-set. Completion offers only what exists at render time, and Ctrl+click goes to where a variable was declared.

⤢ Click to enlarge
component.js

The framework on top of JavaScript

Odoo layers its own module system, Owl components, registries, services and hooks over plain JavaScript. DevKit follows all of it, so completion and navigation know what a registry key or a service name points at.

⤢ Click to enlarge
queries.sqlPro

Raw SQL, still Odoo-aware

cr.execute(...) steps outside the ORM, so a generic SQL plugin has no idea sale_order_line is one of your models. DevKit maps the table back, completes real columns, and Ctrl+click on a column opens the Python field behind it.

⤢ Click to enlarge
problems.log

Warnings tied to your Odoo version

<tree> became <list> in Odoo 18; attrs= was removed one release earlier. DevKit checks each addon against the version it detects, not a generic rule set. It flags real risk too, like sudo() inside a public route handing data to anonymous visitors.

Built for large, multi-addon Odoo codebases

The parts of Odoo's ORM that break simpler tools, or make them slow, are the parts Odoo DevKit is designed around.

▸

Multiple Odoo versions, kept separate

Several Odoo versions can sit in one project. Every lookup is scoped to the addon's own version and dependencies, so a v16 model never turns up in v18 completion.

▸

_inherit vs _inherits, handled correctly

SQL columns and ORM fields follow different rules for _inherit and _inherits. DevKit models both, instead of collapsing them into one mechanism.

▸

Stays fast on heavily-extended models

Lookups go through a search index rather than re-reading every file on each keystroke, even for a model extended across dozens of addons.

▸

Tested against Odoo source

Automated tests check behavior against Odoo's own source, version by version.

Good to know

Which IDE do I need?

PyCharm Community or Professional, 2026.2 (build 262) or newer. SQL and CSS need Professional, with its bundled plugin enabled. JavaScript and Owl work in both editions, within Community's own more limited JavaScript support.

Will Odoo DevKit support other IDEs?

PyCharm is the only one today. The engine isn't tied to a single editor, so others may follow. Tell us which one you need.

Which Odoo versions are supported?

Odoo 10 and up. The active version is detected from your source and manifests, and several versions can share one workspace without clashing.

Does my code ever leave my machine?

No. Analysis and indexing run locally in your IDE, and nothing is uploaded.
